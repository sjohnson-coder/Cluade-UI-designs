# V15.3.2 Nonblocking Runtime Recovery

## Scope
This release addresses UI freezes, stale readiness data, live-loop contention during research jobs, AI-key display ambiguity, inconsistent typography, predictor diagnostics feedback, and Dashboard placement of Early Intent beside Protected Burst.

## Definition of Done

| Phase | Done criteria | Evidence |
|---|---|---|
| Readiness path | `/api/readiness` performs no MT5 or validation work on the request thread; snapshot refreshed every second | Cached readiness worker and focused regression test |
| Live-loop protection | Backtest, validation, walk-forward and sweeps are serialised and yield CPU time | One research worker slot, cooperative progress yield, job heartbeat |
| Stale-state isolation | A non-critical page timeout cannot mark the entire trading runtime stale | Critical-path-only stale event logic |
| AI key persistence | Saved key remains server-side, blank input means unchanged, UI explicitly shows configured state | `apiKeyConfigured`, masked response, focused test and runtime UI enhancement |
| Early Intent dashboard | Early Intent and Protected Burst appear together at equal responsive card size | Runtime pair layout and existing live predictor card |
| Diagnostics feedback | Refresh control visibly enters refreshing, success, or retry state | Predictor and runtime refresh handlers |
| Typography | AI Agent, forms, cards, metrics and controls use one UI font stack | Global Inter/Segoe UI font enforcement |
| Research integrity | Backtest and forward-test jobs retain progress, cancellation and result persistence | Existing async job endpoints plus serial worker and heartbeat |
| Build identity | Backend, frontend, launchers, settings and Tick Guard identify V15.3.2 | Release verifier |
| Regression | Full backend suite passes from release tree | 464 passed |
| Frontend assets | All production JavaScript parses | Node syntax verification |
| Archive | Manifest, checksums, safe extraction and ZIP CRC pass | Release verifier and ZIP test |

## Important operating behaviour
Research jobs no longer run two CPU-heavy workloads simultaneously. This can make a second queued job start later, but preserves quote processing, protection and dashboard responsiveness. Readiness is fail-closed if its background snapshot becomes stale for more than five seconds.
