# GodMode Gold Bot V15.2.5 Live Tick Root Fix

Build ID: `V15.2.5-PREDICTOR-STATUS-RECOVERY`

## Root causes corrected

1. **Millisecond tick timestamps were discarded.** MT5Bridge emitted `timeMsc`, but both anticipatory engines consumed `time_msc`. They fell back to integer seconds, corrupting sub-second velocity and acceleration.
2. **The Settings diagnostics read the wrong API shape.** The backend stored predictor state globally, while the UI looked inside `last`, causing a healthy engine to display `OFFLINE`.
3. **Intent qualification had a hidden second confidence gate.** A 68% Early Intent decision still had to exceed the generic 72% scout floor before execution.
4. **Each predictor fetched ticks independently.** This created inconsistent samples and unnecessary MT5 calls. Both engines now share one canonical rolling tick buffer.
5. **Full-window net movement could cancel the latest burst.** An initial micro-pullback delayed recognition of a later accelerating tail.
6. **Sparse but valid tick windows were treated as fully offline.** The engine now reports `COLLECTING`, uses a bounded hard floor and applies a sample-confidence penalty.
7. **Legacy forming-candle alerts could flip BUY to SELL inside the same M5 candle.** Direction is now locked unless a fresh predictor-confirmed reversal exists.
8. **Legacy spike quality was hardcoded at 82%.** Fallback quality now comes from fresh predictor probability or a bounded displacement calculation.
9. **Predictor diagnostics stopped when a bot position was open.** Scanning now continues for monitoring and confirmation while duplicate entry alerts remain suppressed.
10. **Several UI settings were not connected to backend behaviour.** Dynamic thresholds, live-candle analysis and progressive-execution flags are now consumed by the predictor.
11. **Fresh-install defaults omitted the predictor configuration.** The complete Early Intent and Early Impulse schema now exists in backend defaults and packaged settings.
12. **Cross-field settings could be contradictory.** Validation now rejects hard minimum ticks above target ticks, probe thresholds above confirmation thresholds, and invalid displacement relationships.

## Operational expectations

A connected active market should display `COLLECTING` briefly, then `WATCH`, `INTENT`, `PROBE` or `CONFIRMED`. It should not remain `OFFLINE` merely because no trade is present.

The legacy `Momentum Spike Detected` message is a fallback alert, not the early trigger. Early execution is driven by the Early Intent and Early Impulse states before that fallback threshold is reached.

## External certification still required

No automated Linux test can certify Windows MetaEditor compilation or a broker's live tick frequency, minimum volume, spread, slippage and rejection behaviour. The package remains live-locked until those checks are completed on MT5.
