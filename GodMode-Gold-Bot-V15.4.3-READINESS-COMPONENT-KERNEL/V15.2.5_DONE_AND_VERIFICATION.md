# GodMode Gold Bot V15.2.5 Predictor Status Recovery

## Incident reproduced

The Early Impulse Settings card showed `STARTING` and `Backend unavailable` while the full health page reported a connected live MT5 backend and all listed subsystems healthy.

This was a split-health defect, not a whole-backend outage.

## Root causes

1. `/api/fast-sniper/status` executed a fresh market decision during every diagnostics poll. The Settings page polled every two seconds, so the route competed with the sub-second trading lane for MT5 terminal IPC and could exceed the frontend timeout.
2. The full health page did not include the Priority Intent task. It could report every listed subsystem healthy even when the new priority lane had not produced its first scan, was stale, or had stopped.
3. The Priority Intent task had no dedicated supervisor. A task exception could leave the UI in `STARTING` indefinitely.
4. The deployed page loaded overlapping legacy predictor scripts and reused old asset names. Browser caching and duplicate polling could preserve a stale predictor card after an upgrade.
5. The UI error message incorrectly labelled a predictor-status timeout as `Backend unavailable`, despite the general backend being healthy.

## Corrections

### Read-only predictor status endpoint

`GET /api/fast-sniper/status` now returns cached predictor and priority-lane state only. It does not run a strategy decision, fetch candles, or request a new MT5 tick window.

The response includes:

- endpoint status and response latency
- Early Intent and Early Impulse cached states
- Priority Intent task health
- last scan age and expected interval
- task presence and task completion state
- current blocker
- active build identity
- MT5 connection state

### Priority Intent liveness and recovery

The Priority Intent task now has:

- an explicit task handle
- startup registration
- shutdown cancellation
- a three-second liveness supervisor
- dead-task restart
- stale-heartbeat restart
- runtime-health reporting

### Health page truthfulness

The full health page now includes a dedicated `Priority Intent Execution` component. It cannot silently count the general decision loop as proof that the priority lane is working.

### Frontend recovery

The production page now loads one versioned predictor settings bundle:

- `early-impulse-settings-v1525.js`
- `early-impulse-settings-v1525.css`

The duplicate legacy Early Intent overlay is no longer loaded. Main production assets are versioned with `V1525-PREDICTOR-STATUS-RECOVERY` to force browser cache invalidation.

A predictor-status failure now says:

`Predictor status endpoint unavailable. General backend health may still be live.`

It no longer falsely reports the entire backend as unavailable.

## Expected runtime behaviour

After startup, the Early Impulse card may briefly show `STARTING`, then it should progress to `COLLECTING`, `WATCH`, `INTENT`, `PROBE`, or `CONFIRMED` according to tick availability and market conditions.

The full health page should include `Priority Intent Execution`. If that task becomes stale or crashes, it is displayed as unhealthy and the supervisor restarts it.

## External validation still required

Automated verification cannot reproduce every broker-specific live condition. Demo forward testing remains required for MT5 tick frequency, spread, minimum lot, order acceptance, slippage, disconnections, terminal restarts, and market-session transitions.
