# GodMode Gold Bot V15.2.7

## Context-Qualified Probe and Stage-Specific Risk Control

**Build:** `V15.2.7-CONTEXT-QUALIFIED-PROBE`  
**Version:** `15.2.7`

## Why this release was required

Live demo evidence showed that the V15.2.6 Early Intent lane was active and could place orders, but it could misclassify terminal acceleration as the beginning of a new impulse. A short tick burst near the top of an extended rise could produce a late BUY, while a final burst near the bottom of a large decline could produce an exhaustion SELL.

The same evidence exposed two additional structural problems:

1. A configured probe-size multiplier could not reduce a 0.01-lot base order below the broker minimum. The system could therefore submit 0.01 lot while describing the order as a reduced probe.
2. Early probes entered the ordinary trade-management machinery too soon, inheriting stop widening, recovery breathing, broad structure management and pyramiding before the setup had proved itself.

V15.2.7 corrects those mechanisms rather than making the detector faster or lowering entry thresholds again.

## Root causes corrected

### 1. Local acceleration lacked market-location context

The early engine primarily scored tick velocity, acceleration, persistence, spread and structural proximity. Those signals can occur both at the start and at the end of a directional move.

A new deterministic `IntentContextAssessment` now evaluates cached M5 and M15 data without adding MT5 or network latency. It checks:

- M5 price, EMA20 and EMA50 alignment
- M15 alignment or a valid directional transition
- RSI and stochastic exhaustion
- Recent directional-leg displacement in ATR
- Consecutive directional run length
- Position inside the recent 20-bar range
- Live EMA extension
- Structure score and reversal penalty
- Terminal-acceleration conditions

A candidate cannot become an actionable probe when the context gate identifies an extended or exhausted terminal burst.

### 2. Raw MT5 rates do not contain EMA fields

The predictor lanes previously attempted to read `ema20` from raw MT5 rate rows. When that field was absent, they silently fell back to the current close and reported zero extension.

V15.2.7 derives EMA20 directly from cached M5 closes through `_predictor_extension_atr`. The anti-chase extension measurement is now valid even when MT5 supplies only OHLCV rows.

### 3. Probe stop distance was not stage-specific

The ordinary XAUUSD stop floor could permit a wide stop for a very early entry. The new `build_probe_stop` routine creates a structure-aware probe stop with configurable minimum and maximum price distances.

A probe is rejected when:

- its structural invalidation is invalid;
- the recent structure requires more distance than the probe cap; or
- ATR-based protection exceeds the maximum probe stop.

Default probe-stop range:

- minimum: `1.50` XAUUSD price points;
- maximum: `3.50` XAUUSD price points;
- ATR component: `0.45 ATR`;
- structure buffer: `0.05 ATR`.

### 4. Broker-minimum volume could exceed probe risk

The sizing pipeline now accepts an explicit probe-risk percentage and calculates risk before broker-volume normalisation.

When the broker minimum lot exceeds the configured probe cash-risk budget, the setup is marked `untradeableAtBrokerMinimum` and the order is blocked. It is not rounded up and submitted as a nominal probe.

Default probe account risk: `0.12%`.

### 5. No explicit probe lifecycle

Anticipatory entries now carry a persistent stage and management profile:

```text
PROBE -> CONFIRMED
```

Promotion is one-way and requires either:

- a same-direction confirmed impulse at the configured probability; or
- sufficient open profit with persistent same-direction intent.

Until promotion, the position remains a probe.

### 6. Ordinary management was unsafe for unconfirmed probes

While a position is in `PROBE` stage:

- dynamic stop widening is disabled;
- recovery monitoring is disabled;
- AI dynamic breathing is disabled;
- legacy `RECOVER`, `WIDEN` and `BREATH` directives are removed;
- pyramiding is disabled;
- generic conditional time-stop logic is bypassed;
- probe-specific fast-fail, stall and acceleration-collapse exits apply;
- probe-specific break-even and M5/tick trailing thresholds apply.

After promotion to `CONFIRMED`, ordinary M5 trend management becomes active.

### 7. Unsafe packaged defaults were restored to conservative values

The release defaults now use:

- primary timeframe: `M5`;
- normal risk per trade: `0.25%`;
- probe risk: `0.12%`;
- maximum open trades: `1`;
- maximum daily loss: `2%`;
- equity stop: `8%`;
- pyramiding: disabled;
- maximum packaged volume in restricted mode: `0.01`;
- live trading: disabled;
- dry run: enabled;
- live certification: required.

A one-time migration replaces only exact known legacy defaults. Explicit custom values are preserved.

## Settings and diagnostics added

The Early Impulse settings interface now exposes:

- Context Quality Gate
- Require M15 support
- Context minimum score
- Maximum fresh-leg displacement
- Maximum directional run bars
- Terminal swing-edge threshold
- Maximum context extension
- Probe risk percentage
- Minimum and maximum probe stop
- Probe stop ATR
- Promotion profit threshold
- Probe stall timeout
- Probe fast-fail threshold
- Probe break-even threshold
- Probe trailing start and ATR width

The live dashboard and Settings diagnostics display context and lifecycle information separately from raw intent probability.

## Definition of Done

### Phase 1: Context qualification

Done required:

- Early Intent and Early Impulse use the same deterministic context gate.
- The gate uses cached data only and performs no new network or broker request.
- Fresh expansion can pass.
- Terminal acceleration is blocked.
- M15 support, M5 structure, extension and exhaustion are represented in the decision record.

**Result:** Done. Covered by focused behavioural and integration tests.

### Phase 2: Truthful extension measurement

Done required:

- Raw MT5 OHLC rows without `ema20` produce a real EMA-extension value.
- Early Intent and Early Impulse use that value.
- The old close-as-EMA fallback no longer reports zero extension.

**Result:** Done. A regression test was written and observed failing before implementation, then passed after the fix.

### Phase 3: Probe stop and broker-minimum risk

Done required:

- Probe stops are structure-aware and bounded.
- Excessive structural stop requirements block the setup.
- Sizing uses the configured probe-risk percentage.
- Broker-minimum volume is rejected when it exceeds the risk budget.

**Result:** Done.

### Phase 4: Stage-specific management

Done required:

- Every anticipatory trade is tagged `PROBE` or `CONFIRMED`.
- Promotion is one-way and evidence-based.
- Probe widening, breathing, recovery and pyramiding are disabled.
- Probe fast-fail, stall, opposite-signal and acceleration-collapse rules are active.
- Confirmed positions return to normal management only after promotion.

**Result:** Done.

### Phase 5: Configuration and migration

Done required:

- New settings have defaults, validation bounds and cross-field validation.
- Root and backend packaged settings match exactly.
- Unsafe known legacy defaults migrate once.
- User-customised values are preserved.

**Result:** Done.

### Phase 6: UI continuity

Done required:

- New controls use the current dashboard styling.
- Existing theme, spacing and responsive patterns remain unchanged.
- Production assets reference the V15.2.7 build.
- Live diagnostics display context and lifecycle state.

**Result:** Done at packaged-production-asset level.

### Phase 7: Release identity and integrity

Done required:

- Backend, frontend, launcher, settings, live-certification template and Tick Guard identify the same build.
- Tick Guard source property is `15.027`.
- Runtime logs, databases, snapshots, caches and model artefacts are excluded.
- Manifest and SHA-256 file list match the final tree.
- The ZIP passes extraction, CRC and release verification.

**Result:** Done. The final tree and ZIP passed manifest, checksum, safe-extraction, CRC and clean-package verification.
