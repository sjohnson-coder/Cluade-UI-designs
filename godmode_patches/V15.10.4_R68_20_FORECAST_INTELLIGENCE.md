# V15.10.4 R68.20: forecast intelligence, calibration, abstention and load latency

R68.20 closes the intelligence, prediction and forecasting gaps found by auditing
R68.19, fixes the cause of slow UI loading, and surfaces the new capability in the
Intelligence page. It makes no directional claim and does not enable live trading.

## 1. Slow loading: every asset was being re-downloaded on every page load

`backend/app.py` applied this to **all** `/assets/*` responses:

    Cache-Control: no-store, max-age=0, must-revalidate

`no-store` forbids the browser from keeping the file at all — not even a
revalidation request is permitted. The shipped bundle is 58 files totalling
1,776 KB, and every one of them is **content-hashed** (`Charts-DKRASZbs.js`,
`inter-latin-400-normal-C38fXH4l.woff2`). Content-hashed names are immutable by
construction: change the content and the filename changes. The whole UI was
therefore re-downloaded on every page load and every route navigation.

`services/asset_cache_policy.py` splits `/assets/*` into two classes:

| class | example | header |
|---|---|---|
| content-hashed (53 files, 1,186 KB) | `Charts-DKRASZbs.js` | `public, max-age=31536000, immutable` |
| build-id named (5 files, 590 KB) | `index-V15104-R7-...js` | `public, no-cache` (ETag revalidation) |

The second class is named after the build id rather than the content, so a rebuild
that kept the same id would reuse the filename. Those revalidate instead, which
still yields a ~200-byte `304 Not Modified` rather than re-sending 196 KB.

`/api/` and `index.html` are untouched and remain `no-store`.

Verified against a running server: hashed chunk returns
`public, max-age=31536000, immutable`; the index bundle returns `304 Not Modified`
on a conditional request; `/api/` still returns `no-store`. **Warm-load transfer
drops from 1,776 KB to roughly 1 KB of conditional requests.**

Backend import cost was also profiled: ~560 ms warm, of which 214 ms is app.py's
own module-level execution. That is not the cause of the reported slowness and is
left alone rather than restructured speculatively.

## 2. Volatility forecasting

Grepping the shipped backend for `HAR`, `GARCH`, `EWMA`, `isotonic`, `platt`,
`conformal`, `abstain`, `ood` or `mahalanobis` returned **zero hits**. The bot
scored direction and had no model for magnitude — which is the half of the problem
the data actually supports:

    yesterday's ATR14  -> today's true range    R2 = 0.5625
    yesterday's return -> today's return        R2 = 0.00018

`services/forecast_intelligence.py` adds a HAR-RV model (Corsi 2009), fitted by
ordinary least squares over a rolling window of completed daily bars. Pure Python,
no numpy, no training loop, safe in the hot path.

**Walk-forward validation on 2,604 out-of-sample days (2016-07 to 2026-08):**

| model | R2 | MAE | QLIKE |
|---|---:|---:|---:|
| HAR-RV | **0.657** | **$11.19** | **0.0879** |
| ATR14 baseline | 0.553 | $11.54 | 0.0934 |
| ATR20 baseline | 0.537 | $11.77 | 0.0958 |

HAR wins in 7 of 11 years, and specifically in every high-volatility year (2020,
2022-2026) where sizing errors are expensive. ATR is marginally better in the
quiet years, where the absolute error is small either way.

The forecast is also split across sessions using measured medians (NY AM 0.572
ATR, London 0.404, Asia 0.377, NY PM 0.310).

## 3. Probability calibration

`services/v15/calibration.py` had the *metrics* (Brier, reliability bins, ECE) but
no fitted calibrator, so a miscalibrated confidence score was measured and then
used anyway.

`services/calibration_engine.py` adds Platt scaling and isotonic regression
(pool-adjacent-violators), selected against each other on a **chronological**
holdout — a random split leaks the future, because probability quality drifts with
regime. If neither beats the raw score, an identity calibrator is returned and the
report says so.

It is fitted only on real closed bot trades; seeded sample rows are excluded,
because calibrating against fiction is worse than not calibrating.

## 4. Abstention and out-of-distribution detection

The bot always had an opinion. It can now decline.

`services/abstention_gate.py` combines two independent signals:

- **novelty** — RMS per-feature z-score of the live feature vector against a
  running Welford distribution. Catches "this state is unlike anything learned".
- **disagreement** — spread across independent signal sources. Catches "the inputs
  contradict each other", which a distance check cannot see.

The policy is three-state (`TRADE` / `REDUCE` / `ABSTAIN`) rather than binary. A
cold start returns `REDUCE`, not `ABSTAIN`: insufficient history is not evidence of
an unusual market.

## 5. UI

A `ForecastIntelligence` panel is added to the Intelligence overview tab, showing
tomorrow's expected range and its 80% interval, the session split, the abstention
state with its reason, calibration before/after, the live cost-gate minimum stop,
and which policy blocks are currently suppressing repeat alerts. Every panel states
its degraded reason rather than showing a blank.

## 6. Grade

`grade_bot.py` scores 33 criteria across 7 categories by checking the source tree
and settings, not by assertion.

| category | score | grade |
|---|---:|:--:|
| Execution integrity | 9/9 | A |
| Risk control | 13/13 | A |
| Intelligence & forecasting | 13/13 | A |
| Trade management | 7/7 | A |
| Observability & notification | 8/8 | A |
| Performance | 5/5 | A |
| **Proof of edge** | **3/16** | **F** |
| **OVERALL** | **58/71** | **A-** |

The A- is for build quality. "Proof of edge" is the most heavily weighted category
and it fails: there is no live broker record, no positive out-of-sample expectancy
after costs, and no completed canary. That separation is deliberate — a grade that
let good engineering paper over an unproven strategy would be worse than none.

## Verification boundary

Full backend suite: **1,276 passed, 6 failed, 1 skipped**. The same 6 failures
occur on the unmodified R68.18 tree in this environment (runtime-lane and scheduler
concurrency tests needing an unconstrained host). `compileall` clean, frontend
`tsc --noEmit` clean, production build clean, and the new Intelligence panel was
rendered in a real browser against a running backend with zero console errors.

Two regressions were introduced during this work and caught by the repo's own
tests before packaging: a baseline/identity mismatch and a banned pass-only
exception handler. Both are fixed.

MetaEditor, a live MT5 terminal, real Telegram delivery and broker fills remain
environment-dependent and require a demo canary. The release ships disarmed:
`dryRun=true`, live and auto trading disabled, research overlay in SHADOW.
