# V15.10.4 R68.19: execution economics and notification integrity

R68.19 closes the gaps found by auditing R68.18 against two independent XAUUSD
research reviews. It changes notification behaviour, adds two deterministic
execution gates, and corrects a lot-cap defect. It makes no directional claim and
does not enable live trading.

## 1. Telegram: policy blocks are no longer reported as execution failures

**Symptom.** Repeated identical `🔴 GodMode — Order NOT filled` alerts, one per
scan cycle, for the whole duration of a high-impact news window.

**Cause, part one.** `_telegram_minimal_category` routed a message into the
throttled `rejection` class only on `"trade rejected"`, `"order rejected"`,
`"rejection summary"` or `"order not sent"`. The alert says *"Order NOT filled"*,
which matches none of them, so it fell through to the `other` class. The
`rejection` class keys on `f"rejection:{bucket}"` — one alert per window whatever
the reason — while `other` keys on a SHA-256 of the full message text, so any
variation in the reason string produced a new alert.

**Cause, part two.** `_execute_mt5_serialized` returns the `_news_entry_guard`
block dict, and the direct runner treated every non-`ok` result as an execution
failure. A known, self-clearing policy decision was therefore reported on the same
red channel as a genuine broker rejection, once per retry.

**Change.**

- New `services/telegram_event_policy.py` classifies a failed dispatch as
  `policy_block`, `execution_failure` or `unknown`.
- Policy blocks pass through `BlockLatch`, which alerts on the transition into the
  state and then at most once per `remind_after_seconds` (default 900).
- A broker-confirmed fill clears the latch and emits one all-clear naming how many
  setups were skipped.
- Execution failures are unchanged: they always alert. R48's guarantee that a
  DISPATCHED never ends in silence is preserved.
- `_telegram_minimal_category` now also routes `"order not filled"`,
  `"entries paused"` and `"entries resumed"` to `rejection`.
- `_telegram_market_closed_silence` gained an explicit exception so that this
  policy chatter does **not** inherit the `rejection` class's exemption from the
  market-closed silence. A genuine broker rejection still passes straight through.
- A pre-dispatch `_news_entry_guard` check on the direct path stops a known
  blackout from reaching DISPATCHED at all.

**Effect.** The five-alert burst in the reported screenshot becomes one message. A
30-minute news window scanned every two seconds drops from up to 900 alerts to
two. The dashboard, journal and notification store still record every attempt.

## 2. Cost-relative minimum stop

Measured on 4,077,891 M1 XAUUSD bars (2015-01 to 2026-08), with only the stop
distance varied and the entry model held constant:

| stop | median stop | cost as % of risk | gross expectancy | net expectancy |
|---|---:|---:|---:|---:|
| 0.08 ATR | $1.75 | 21.8% | -0.003 R | -0.221 R |
| 0.25 ATR | $5.48 | 7.0% | -0.006 R | -0.076 R |
| 0.35 ATR | $7.67 | 5.0% | -0.006 R | -0.056 R |
| 1.00 ATR | $21.92 | 1.7% | -0.001 R | -0.019 R |

Gross expectancy is flat at every stop size. The entire 0.20 R spread is
transaction cost, because a fixed dollar cost expressed in R is inversely
proportional to stop distance. A tighter stop does not improve R:R; it multiplies
the toll the spread takes from every trade.

`services/cost_relative_stop.py` adds `stop >= minStopCostMultiple x (spread +
entry slippage + exit slippage)`, default multiple 20, which caps cost at 5% of
risk. It is applied to every Protected Burst leg, because each leg enters later
and worse on the same stop distance and so carries a worse cost ratio than the
first.

`automation.earlyIntentProbeMinStopPoints` is left at 1.5 deliberately: it is a
fixed point floor that cannot track a moving spread, and the new gate is strictly
stricter at every realistic spread ($8.80 minimum at a $0.44 round trip), so it is
now non-binding rather than removed.

## 3. Protected Burst lot caps now actually bind

With `enforceSeparateLotCap=false`, `_burst_leg_lots` took its ceilings from
`pyramiding.maxLot` and `pyramiding.maxTotalLots` (both 4.0), **not** from the
operator-visible `protectedBurst.maxPerPositionLot` (0.05) and
`protectedBurst.maxTotalLots` (0.10). The UI showed a 0.10-lot campaign cap while
the enforced ceiling was 4.0 lots — a 40x gap.

`enforceSeparateLotCap` is now `true`, with the Burst caps set to the values the
ladder actually needs (0.08 per leg, 0.18 total). This lowers the enforced ceiling
from 4.0 lots to 0.18 and changes no traded volume.

## 4. Descending Burst ladder

`startLot=0.04` with `lotIncrement=+0.02` produced `0.04 -> 0.06 -> 0.08`: more
size at progressively worse prices. The ladder is now `0.08 -> 0.06 -> 0.04` via
`startLot=0.08`, `lotIncrement=-0.02`. Total basket volume is unchanged at 0.18
lots; the largest leg now sits at the best price and each add reduces marginal
risk. The `move()` migration guard only rewrites a value that exactly equals its
known-bad default, so these settings are preserved across upgrade.

## 5. Burst arming requires room, not just time

`services/burst_session_room.py` compares the range realised so far in the current
session against that session's historical median, measured from the same sample:

| session | median range (ATR) | p90 |
|---|---:|---:|
| NY AM 08:00-12:00 | 0.572 | 1.048 |
| London 02:00-08:00 | 0.404 | 0.704 |
| Asia 18:05-02:00 | 0.377 | 0.683 |
| NY PM 12:00-17:00 | 0.310 | 0.640 |

A ladder needs continuation to exist. The gate fails open when range or ATR is
unavailable, so it can only refuse a burst, never authorise one.

## 6. Intraday session weights are kept separate from exposure weights

The R68.18 clock policy weights were derived from **holding** exposure, where New
York produced a -0.03 Sharpe over 11.7 years. An intraday bot enters and exits
inside a session, which is a different measurement. A new intraday test (2,992
trades per session, costs charged) ranks NY AM **best**, not worst, and finds Asia
is the only session where breakout beats fade while London and New York prefer
fade.

`ai.researchClockIntradaySeparateWeights=true` and
`ai.researchClockIntradayWeights` (all 1.0 by default) keep the two vocabularies
apart so the exposure weight can never be reused as an intraday entry switch.
`researchClockPolicyMode` remains `SHADOW`.

## Verification boundary

Full backend suite: **1258 passed, 6 failed, 1 skipped**. The identical 6 failures
occur on the unmodified R68.18 tree in the same environment (runtime-lane and
scheduler concurrency tests that require an unconstrained host); the patched tree
adds 8 passing tests and introduces no new failure. `python -m compileall backend`
is clean.

MetaEditor, a live MT5 terminal, real Telegram delivery and broker fills remain
environment-dependent and require a demo canary on the target terminal. The
release ships disarmed: live and auto trading disabled, research overlay in
SHADOW. None of these changes creates a directional edge or authorises live
trading.
